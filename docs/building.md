# Fresh checkout setup

The supported baseline is Ubuntu 24.04 or Linux Mint 22 on x86-64, with Python
3.10+ and LLVM/MLIR 19. The verified local environment uses Python 3.12 and the
pinned Ubuntu LLVM/MLIR 19.1.1 packages.

## First run

Install the small host prerequisites if they are not already available:

```bash
sudo apt-get update
sudo apt-get install build-essential cmake ninja-build graphviz python3-venv
```

Then, from a fresh clone:

```bash
./scripts/setup-dev.sh
./scripts/check.sh
```

Setup creates `.venv`, installs the pinned dependencies in `dev/requirements.txt`,
installs Hintz in editable mode, and builds the dialect tools. It reuses a system
SDK at `/usr/lib/llvm-19` if available; otherwise it downloads the pinned packages
in `dev/llvm-packages.txt` and extracts them into `tools/llvm/`. Setup never runs
sudo or changes system packages. Initial setup requires access to PyPI and the
Ubuntu package repositories and several GB of free space.

Use `--local-llvm` for the pinned repository-local SDK even when system LLVM is
installed (CI uses this mode). To use another complete LLVM/MLIR 19 SDK:

```bash
./scripts/setup-dev.sh --llvm-prefix /path/to/llvm-19
```

The SDK must contain the LLVM and MLIR CMake development files, `llvm-config`,
`clang`, `mlir-opt`, `mlir-translate`, `mlir-tblgen`, and LLVM test utilities.
`PYTHON_BIN` selects the Python used when creating `.venv`; `BUILD_JOBS` controls
build parallelism (default 2). An existing virtual environment is reused.

## Everyday use

No environment activation or PATH configuration is required:

```bash
./scripts/hintz --version
./scripts/hintz samples/scalar_pipeline.hz --out /tmp/hintz-scalar
/tmp/hintz-scalar
echo $?  # 42
```

The launcher can be invoked by absolute path from another working directory.
Source and output paths remain relative to your current directory. It selects
the checkout's Python and native tools; explicit compiler tool flags can still
override them.

To keep all intermediate files:

```bash
./scripts/hintz --emit-hintz-mlir --emit-lowered-mlir --emit-llvm --emit-exe \
  --out /tmp/hintz-scalar samples/scalar_pipeline.hz
```

The flow is Hintz -> arith/func/memref -> LLVM dialect -> LLVM IR -> Clang. Outputs
are `.hintz.mlir`, `.lowered.mlir`, `.llvm.mlir`, `.ll`, and the native executable.

## Verification

`./scripts/check.sh` rebuilds the dialect, runs the Python suite (including native
and installed-CLI integration tests), runs the dialect tests, and compiles/runs
the scalar sample. It checks that all intermediate files exist and the executable
returns 42. Missing tools, failed tests, or skipped Python tests fail the command.
Reports and sample artifacts are stored in ignored `tools/check-results/`.

Clean-clone verification on 2026-09-18: setup and repeated setup succeeded;
103 Python tests and 8 dialect tests passed; the native sample returned 42.

The optional MLIR Python-binding smoke test is reported separately as disabled.
Those bindings require an upstream SDK with Python bindings and C API aggregate
objects; the compiler's command-line pipeline does not use them. All other dialect
tests must pass. The GitHub Actions workflow repeats setup and runs the same gates
on a fresh Ubuntu 24.04 checkout without prepopulated project caches.

## Repeatability and troubleshooting

- Rerun setup after pulling dependency or build changes. Downloaded packages,
  pip downloads, the virtual environment, and incremental build outputs are reused.
- LLVM package versions and Python dependencies are pinned in `dev/`. Update those
  manifests deliberately and run the complete gates before committing an update.
  An external/system SDK is validated as LLVM 19 but is not patch-version pinned.
- If `apt-get download` cannot find a pinned revision, refresh the host's package
  indexes with `sudo apt-get update`. If the archive no longer provides it, use
  `--llvm-prefix` or update the manifest and verify the new revision.
- If a tool cannot load a shared library, inspect it with `ldd`. Repository-local
  extraction still uses Ubuntu's host runtime libraries; it is not a portable SDK.
- If the SDK extraction is damaged, remove `tools/llvm/.packages.sha256` and rerun
  setup to extract the cached packages again.
- If Python's venv module is missing, install `python3-venv` (or the matching
  package for the selected Python). Setup reports missing host prerequisites.
- To change Python versions or move the checkout, recreate `.venv` and
  `hintz-mlir-dialect/build`, then rerun setup. These contain absolute paths.
  Tool wrappers are regenerated by setup and refer to the SDK's absolute location.
- Build products and downloads stay under ignored `.venv/`, `tools/`, and
  `hintz-mlir-dialect/build/`. They must not be committed.

## Backend scope

The complete pipeline works for integer constants, addition, scalar assignments,
loads/stores, and value returns in straight-line functions. Values currently use
`i64`. The frontend accepts more syntax than this backend implements.

Native support for branches/loops and SSA joins, function calls and parameters,
additional operators, floating-point types, arrays/structs/matrices and full
ABI/type mapping remains future work. See `HINTZ_MLIR_PLAN.md`; a passing minimal
pipeline does not mean those stages are complete.
